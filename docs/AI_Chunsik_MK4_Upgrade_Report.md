## 🛠️ 1. 핵심 개선 사항 (Key Features)

### 🛡️ Part 1. 가짜 데이터 봉쇄 및 데이터 신뢰성 확보 (Data Quality)
* **가짜 퀀트 리포트 폴백 전면 제거**
  * 로컬 LLM(Ollama) 호출 실패 시, 기존에 하드코딩된 예시 템플릿(가짜 리포트)을 그대로 최종 렌더링하던 로직을 전면 차단했습니다.
  * 호출 실패 시 `None`을 반환하며, 해당 데이터는 `is_degraded = True` 상태로 마킹됩니다.
* **소셜 스크래퍼 하드코딩 제거**
  * StockTwits, Reddit, Toss 인기 주식 스크래퍼에서 통신 장애 및 API 차단(HTTP 403, 429 등)이 일어났을 때, 임의의 고정 수치(소셜 긍정률 62.8%)나 밈 종목 후보군을 가짜로 반환하는 로직을 완전히 삭제했습니다.
  * 실패 시 데이터 출처 신뢰성을 보증하는 `Provenance.unavailable` 상태를 반환하거나 빈 리스트를 리턴하도록 처리했습니다.
* **학습 데이터 격리 및 오염 방지**
  * `reports` 테이블에 `is_degraded` 컬럼을 마이그레이션 적용했습니다.
  * 성찰 엔진(`reflection_engine.py`) 및 프롬프트 빌더(`prompt_builder.py`)의 최근 성과 통계 쿼리에서 `COALESCE(r.is_degraded, 0) = 0` 조건을 필수로 주입하여, 가짜 데이터나 품질이 현저히 떨어진 과거 리포트가 자가학습에 활용되어 지능이 오염되는 구조를 완전히 차단했습니다.
* **보고서 최상단 보증 배너**
  * 분석 데이터가 누락되거나 LLM 장애가 있었던 종목이 포함되는 즉시 일간 종합 리포트의 최상단에 `ReportQuality.banner()` 경고 문구가 자동으로 렌더링됩니다.

### 🔄 Part 2. 실효적 자가학습 및 통계적 백테스터 게이트 (Evolution Gate)
* **부트스트랩 95% 신뢰구간 백테스터**
  * AI가 성찰을 통해 새로운 투자 규칙을 무분별하게 창작하여 적용하던 한계를 보완하기 위해, 과거 200여 개의 결정 흔적(`decision_traces`) 데이터를 연계한 **부트스트랩 95% 신뢰구간 백테스팅 게이트**를 이식했습니다.
  * 제안된 규칙이 실제로 발동되었을 때와 발동되지 않았을 때의 성과 차이(CI)를 통계적으로 시뮬레이션하여 0을 포함하지 않는 유의미한 규칙만 적재합니다.
* **Shadow/Active 규칙 라이프사이클 관리**
  * 규칙들의 상태를 Proposed -> Shadow -> Active -> Retired 단계로 체계화했습니다.
  * 진화한 신규 룰은 최초 `Shadow` 상태로 저장되며, Out-of-sample 성과 추적을 거친 후 95% 신뢰구간 유효성 검증을 통과해야 실제 분석 프롬프트에 활용되는 `Active` 상태로 승격됩니다. 저성과 지속 시 즉시 `Retired` 상태로 은퇴합니다.
* **활성 룰 필터 주입**
  * `prompt_builder.py`에서 `status = 'active'` 상태인 검증된 장기 지식 규칙들만 로컬 LLM의 컨텍스트 프롬프트에 직접 주입되도록 필터를 설계했습니다.

## ⚡ 2. 레이턴시 극복 및 타임아웃 튜닝
로컬 환경(특히 CPU/GPU 메모리 점유가 높은 gemma4:26b 17GB 모델 구동)의 레이턴시 특성을 반영해 시스템 임계치를 튜닝했습니다.
* **오케스트레이터 타임아웃 연장**: 전체 파이프라인 가동 완료 신호 감시 타임아웃을 `config.py`에 **`PIPELINE_TIMEOUT_SEC = 2400` (40분)**으로 정의하여, 복수 종목의 순차 교정이 중단 없이 완주되도록 보장했습니다.
* **벌크 LLM 240초 튜닝**: 여러 종목을 한 번에 추론하는 벌크 프롬프팅(`generate_bulk_ai_narrative`) 시 로컬 LLM 추론 지연으로 타임아웃이 발생하던 현상을 해결하기 위해 전용 타임아웃을 **240초(4분)**로 상향했습니다. 벌크 추론이 한 번에 통과하여 개별 호출 폴백 비용을 감축시켰습니다.

## 🧠 3. 메모리(Memory) 아키텍처 매핑

```
┌────────────────────────────────────────────────────────┐
│                   AI Chunsik MK4 Memory                │
└────────────────────────────────────────────────────────┘
            │                                 │
            ▼                                 ▼
┌───────────────────────┐         ┌───────────────────────┐
│  Short-term Memory    │         │   Long-term Memory    │
│  (인메모리 공유 캐시)   │         │  (SQLite & Prompt)    │
├───────────────────────┤         ├───────────────────────┤
│ - Broker 내 공유 메모리  │         │ - decision_traces     │
│ - Payload Referencing │         │ - learned_rules       │
│ - TTL 30분 자동 소멸   │         │ - Active 룰 프롬프트  │
└───────────────────────┘         └───────────────────────┘
```

### 1) 단기기억 (Short-term Memory)
* **목적**: 에이전트 간 대량 데이터의 물리적 송수신으로 인한 토큰 낭비와 네트워크 병목 최소화.
* **구현**: `MessageBroker`가 관리하는 `self._shared_memory` 해시맵. 에이전트들은 메모리 내의 고유 식별자 해시 태그(`#payload:debate:TICKER`)만 전달받아 필요한 시점에 역참조합니다.
* **소멸**: 기본 30분 TTL을 가집니다. 오케스트레이터 종료 시 즉시 `max_age=0`으로 메모리를 완전히 정리하여 가비지 컬렉션을 가동합니다.

### 2) 장기기억 (Long-term Memory)
* **목적**: 과거의 의사결정 판단과 실제 성과 피드백을 축적하여 시스템을 자가 진화.
* **구현**: SQLite에 보관되는 퀀트 이력(`decision_traces`) 및 진화 규칙(`learned_rules`). 
* **고착화**: 실제 백테스팅을 통과해 `Active`로 승격된 정밀 룰들이 보고서 작성 프롬프트에 자동으로 주입되어 영구적인 시스템 지식으로 정합됩니다.
